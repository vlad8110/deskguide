## 2. Shared conventions

**Roles (server-derived, never trusted from the browser):** `customer`, `agent`, `administrator`.
Administrator rights cover document administration (C8) only. They do **not** grant access to customer conversations, escalations, or raw feedback (C4, C5, C6 content).

**Enum style.** Enum values are lowercase snake_case, matching Collins's flows. Error codes are UPPER_SNAKE.

**Versioning.** `/v1/` path prefix. Responses include `contract_version` (currently `"0.2"` while drafting).

**Headers**

| Header | Rule |
|---|---|
| `Authorization: Bearer <token>` | Required on all endpoints |
| `X-Correlation-ID` | **Server-generated** and returned on every response. Any client-supplied value is ignored (Collins's design). |
| `Retry-After` | Seconds, sent on 429 and 503. Servers should add jitter to avoid synchronized retries. |

**Identifiers**

| ID | Meaning | Generated by |
|---|---|---|
| `correlation_id` | Trace one inquiry across components | Server |
| `inquiry_id`, `answer_id` | An inquiry and its answer | Server |
| `submission_id` | One intentional customer escalation submission; reused on retries | Browser (UUID v4) |
| `request_id` | The durably saved support request | Server |
| `source_id`, `section_id`, `source_version` | Exact evidence reference | Knowledge store |
| `configuration_version` | Prompt, retrieval and model configuration used | Server |

**Common types**

| Type | Definition |
|---|---|
| `Uuid` | UUID v4 string |
| `Timestamp` | ISO 8601 UTC |
| `SourceRef` | `{ source_id: "DOC-003", section_id: "s2", source_version: "3" }`. `source_id` matches `^DOC-[0-9]{3}$`; `section_id` matches `^s[0-9]{1,2}$`; `source_version` is a positive integer string. |
| `AnswerStatus` | `answered`, `clarification_requested`, `escalation_offered`, `temporarily_unavailable` |
| `EscalationReason` | `insufficient_evidence`, `human_requested`, `validation_failed`, `provider_failure`, `action_required` |
| `RequestState` | `queued`, `assigned`, `in_review`, `waiting_for_customer`, `resolved` |

**Error envelope (all non-2xx)**

```json
{
  "contract_version": "0.2",
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Your question must be between 1 and 1000 characters.",
    "retryable": false,
    "correlation_id": "6f1c2a9e-3b7d-4d0a-9c11-2f5e8a7b1d42",
    "details": [{"field": "question", "rule": "length_1_1000"}]
  }
}
```

`message` is safe and user-facing. It never contains stack traces, provider names, SQL, or credentials. `details` appears only for `VALIDATION_FAILED` and lists field names, not values.

| Code | HTTP | Retryable | Meaning |
|---|---|---|---|
| `VALIDATION_FAILED` | 400 | No | Malformed or out-of-range input |
| `UNAUTHENTICATED` | 401 | No | Missing, invalid or expired token |
| `FORBIDDEN` | 403 | No | Role or scope not permitted |
| `NOT_FOUND` | 404 | No | Missing, or outside caller's scope (same response for both) |
| `CONFLICT` | 409 | No | Illegal transition, ownership/version conflict, or reused `submission_id` with different content |
| `RATE_LIMITED` | 429 | Yes | Per-customer limit reached |
| `INTERNAL_ERROR` | 500 | Yes | Unexpected failure, no details exposed |
| `SERVICE_BUSY` | 503 | Yes | Aggregate capacity or queue bound reached; includes `Retry-After` |
| `DEPENDENCY_UNAVAILABLE` | 503 | Yes | Storage or other required dependency down |
| `DEADLINE_EXCEEDED` | 504 | Yes | End-to-end deadline passed |

**Privacy and logging (all contracts).** Permitted log fields: `correlation_id`, normalized error category, duration, `configuration_version`, retry count (Collins). Not logged: question, answer, note, comment text, tokens, provider keys, raw provider errors. *Open (David):* whether `subject_id` may be logged for audit.

**Overload (167 inquiries/s planning basis).**
- Per-customer limits plus an aggregate generation concurrency limit.
- Queue wait time counts toward the end-to-end deadline.
- At capacity: return `SERVICE_BUSY` with `Retry-After`, not unbounded queuing.
- Escalation (C4, C5) has its own capacity limit, independent of generation, so a human handoff stays available when AI is saturated.
- Illustration only: in-flight model calls ≈ model-call rate × mean call duration (Collins §9). Vlad and David own the real numbers.

**Data ownership.** Each component owns its records and rules; others use its interface, not its tables.

| Owner | Records |
|---|---|
| `Retriever` / `DocumentService` (M3) | Documents, sections, versions |
| `EscalationService` / `AgentQueueService` (M6) | Support requests, submission records, states |
| `FeedbackService` (M8) | Feedback, improvement proposals, releases |
| `CustomerDirectoryAdapter` (M7) | No stored copy (read-through, optional short cache) |

## 4. Contracts

### C9. Access context (internal type, defined first because every contract uses it)

**Owner:** `AccessControl` (M2). Built server-side from the validated token. Never accepted from the browser.

```
AccessContext {
  subject_id:     string        # authenticated user, required
  role:           Role          # customer | agent | administrator
  customer_scope: string|null   # customer_id for customers; null for agent/administrator
  tenant_id:      string|null   # null until V20 decided
  correlation_id: Uuid          # server-generated
  issued_at:      Timestamp
}
```

Every internal method takes an `AccessContext` as its first argument. Client-supplied customer, role or scope values are never sufficient authorization.

| Condition | Result |
|---|---|
| Token missing, invalid, expired | 401 `UNAUTHENTICATED` |
| Role not allowed for the endpoint | 403 `FORBIDDEN` |

**Tests:** forged `customer_id` in a body is ignored; customer token calling an agent endpoint returns 403; administrator token calling C4/C5/C6 content endpoints returns 403; expired token returns 401.

### C1. Customer inquiry and answer

**Owner:** `InquiryService` (M2). **Caller:** customer browser. **Interface:** `POST /v1/inquiries`
**Authorization:** `customer` (own inquiries only). Document scope derived server-side.

**Request**

| Field | Type | Req. | Nullable | Constraints |
|---|---|---|---|---|
| `question` | string | Yes | No | 1-1,000 chars after trim; no control characters |
| `conversation_id` | Uuid | No | Yes | Must belong to caller |

**Response 200**

| Field | Type | Nullable | Notes |
|---|---|---|---|
| `inquiry_id` | Uuid | No | |
| `answer_id` | Uuid | Yes | Null unless a candidate answer was produced |
| `status` | AnswerStatus | No | |
| `answer` | string | Yes | Only when `answered`; max 4,000 chars |
| `sources` | array of Source | No | Empty unless `answered`; max 8 |
| `clarification_prompt` | string | Yes | Only when `clarification_requested` |
| `escalation_offered` | boolean | No | True for `escalation_offered` and `temporarily_unavailable` |
| `suggested_reason` | EscalationReason | Yes | Prefill for C4 when escalation is offered |
| `configuration_version` | string | No | |
| `correlation_id` | Uuid | No | |
| `contract_version` | string | No | |

`Source = { ref: SourceRef, title, section_title, url }`. `url` resolves through C2.

**Flow (Collins, Flow A).** Authenticate (C9), validate, derive scope, optionally fetch allowlisted customer fields (C7), retrieve (C2), pre-generation evidence check (V19), generate (C3), validate output (C10), then return.

**Example**
```json
{
  "contract_version": "0.2",
  "inquiry_id": "b1d2c3e4-1111-4a22-8b33-9c44d55e6f77",
  "answer_id": "a9b8c7d6-3333-4c44-9d55-1e66f77a8899",
  "status": "answered",
  "answer": "Install the Acme VPN client, sign in with your demo account, and select the 'Campus' profile.",
  "sources": [{
    "ref": { "source_id": "DOC-003", "section_id": "s2", "source_version": "3" },
    "title": "VPN Setup Guide",
    "section_title": "Installing the client",
    "url": "/v1/sources/DOC-003/sections/s2?version=3"
  }],
  "escalation_offered": false,
  "suggested_reason": null,
  "configuration_version": "cfg-0.1",
  "correlation_id": "6f1c2a9e-3b7d-4d0a-9c11-2f5e8a7b1d42"
}
```

**Outcome and error mapping**

| Condition | Response |
|---|---|
| Invalid input | 400 `VALIDATION_FAILED` |
| No/invalid token | 401 `UNAUTHENTICATED` |
| Conversation not caller's | 403 `FORBIDDEN` |
| Per-customer limit | 429 `RATE_LIMITED` + `Retry-After` |
| Aggregate capacity or queue bound | 503 `SERVICE_BUSY` + `Retry-After` |
| Insufficient, conflicting or stale evidence, or validation fails (C10) | 200 `clarification_requested` or `escalation_offered`; no unsupported answer shown |
| Provider timeout/quota/outage (C3) | 200 `temporarily_unavailable`, `escalation_offered: true`, `suggested_reason: provider_failure`; question preserved in the UI |
| Required customer context unavailable (C7) | 200 `escalation_offered` (controlled; no guessed customer facts) |
| Deadline exceeded | 504 `DEADLINE_EXCEEDED` |

*Open with Collins:* whether provider failure should be 200 with a status (this draft) or 503. The 200 form keeps the response in the normal path so the UI can offer escalation immediately.

**Persistence.** The inquiry (status, source refs, `configuration_version`) is stored before responding. Question text storage is subject to the retention decision (V21).
**Privacy.** Question goes to the provider through C3 only; never logged.

**Tests:** supported question returns `answered` with citations that resolve; unsupported returns `escalation_offered` with no answer; ambiguous returns `clarification_requested`; empty and oversized input return 400; no token returns 401; other customer's conversation returns 403; provider timeout (mock) returns `temporarily_unavailable`; 6th request in a minute returns 429; saturated queue returns 503 `SERVICE_BUSY`; deadline exceeded returns 504 and a late provider result does not replace the fallback.

### C2. Retrieval and source access

**Owner:** `Retriever` (M3).

**C2a. `retrieve(ctx: AccessContext, query: str, top_k: int = 5, deadline_ms: int) -> RetrievalResult`**
**Caller:** `InquiryService` only.

| Input | Type | Constraints |
|---|---|---|
| `ctx` | AccessContext | Scope derived from `ctx.role` and `ctx.customer_scope`; the caller cannot widen it |
| `query` | string | 1-1,000 chars |
| `top_k` | int | 1-8 |
| `deadline_ms` | int | 1-2000 |

Output: `RetrievalResult { passages: [Passage], index_version: string }`, `Passage { ref: SourceRef, text (max 1,500 chars), score 0-1, rank int }`, sorted by rank. An empty list is valid.
Failures: `RetrieverTimeout`, `RetrieverUnavailable` (mapped by `InquiryService` to a controlled response).

**C2b. `GET /v1/sources/{source_id}/sections/{section_id}?version={n}`**
**Authorization:** any authenticated role, within scope. `version` optional (default current). Returns `{ ref, document_title, section_title, text, correlation_id }`.

| Condition | Response |
|---|---|
| Malformed ID | 400 `VALIDATION_FAILED` |
| Missing, removed, or out of scope | 404 `NOT_FOUND` (identical response, so restricted documents are not revealed) |
| Store unavailable | 503 `DEPENDENCY_UNAVAILABLE` |

**Tests:** known section returns 200; old version still resolves when retained; removed source returns 404; agent-only source requested by a customer returns 404; empty retrieval returns an empty list; retriever timeout (mock) raises `RetrieverTimeout`.

### C3. AI generation adapter

**Owner:** `GenerationAdapter` (M4). It translates between the internal request and the provider, normalizes results and errors, and enforces deadlines and call limits. It does **not** authorize, save requests, or validate citations (that is C10).
**Method:** `generate(request: GenerationRequest) -> GenerationResult`
**Caller:** `InquiryService` only.

**`GenerationRequest`**

| Field | Type | Req. | Nullable | Constraints |
|---|---|---|---|---|
| `question` | string | Yes | No | 1-1,000 chars |
| `passages` | array of Passage | Yes | No | 1-8, permitted passages only |
| `approved_context` | object | No | Yes | Only allowlisted fields (V22); no credentials, tokens, or unrestricted records |
| `deadline_ms` | int | Yes | No | 1-15000, based on remaining deadline |
| `configuration_version` | string | Yes | No | |
| `correlation_id` | Uuid | Yes | No | |

**`GenerationResult` (success)**

| Field | Type | Nullable | Notes |
|---|---|---|---|
| `candidate_answer` | string | Yes | Null if the model reports it cannot answer |
| `cited_refs` | array of SourceRef | No | References to supplied evidence |
| `adapter_version` | string | No | |

The result is a **candidate**. It becomes an answer only after C10 passes.

**Failure categories (provider-neutral, Collins Flow C)**

| Category | Meaning | Customer-visible result |
|---|---|---|
| `timeout` | Deadline reached | `temporarily_unavailable` |
| `quota_exceeded` | Provider quota or 429 | `temporarily_unavailable` |
| `service_unavailable` | 5xx or network | `temporarily_unavailable` |
| `invalid_provider_response` | Unparseable or off-contract output | `temporarily_unavailable` (no unsupported answer shown) |
| `provider_configuration_error` | Authentication or configuration failure | `temporarily_unavailable` to the customer; operator alert; no repeated customer retries |

**Rules**
- Check admission limits and remaining deadline before calling the provider.
- Late results are discarded and never replace a completed fallback response.
- Retries only if they fit the deadline, respect provider retry guidance, and stay within the retry budget (V17, open). No indefinite retry.
- No automatic failover to a second provider (deferred; B17 is consolidated into B11).
- Text in passages or customer input is data. Instructions inside it never override policy or grant tools or database access.
- Credentials stay server-side. Only question, passages, and allowlisted context are sent. Never customer database records or tokens.

**Tests:** valid input returns a candidate with `cited_refs`; each failure category maps correctly (mock); passage containing "ignore your rules" does not change behavior; a result arriving after the deadline is ignored; configuration error triggers an operator alert and a customer-safe message; request containing a non-allowlisted field is rejected before the provider call.

### C10. Answer and source validation (new, internal)

**Owner:** `AnswerValidator` (M5). **Caller:** `InquiryService`.
**Method:** `validate(ctx: AccessContext, candidate: GenerationResult, retrieved: RetrievalResult) -> ValidationResult`

```
ValidationResult {
  outcome:         "pass" | "fail"
  failure_reasons: [ "unknown_source" | "version_mismatch" | "access_denied"
                   | "unresolvable_source" | "no_citations" | "malformed_output" ]
  checked_refs:    [SourceRef]
}
```

**Checks (structural):** every `cited_refs` entry is in the retrieved set; versions match; the caller still has access; each reference resolves via C2b; at least one citation exists for an answer.
**Limit:** these checks do not prove the answer is semantically supported. A valid link is not proof of correctness (Gao et al., as cited in the pitch). Semantic support is evaluated manually in B12. The runtime evidence-sufficiency policy is open (V19). Model self-reported confidence is not accepted as proof.
**On `fail`:** the candidate is suppressed and C1 returns `clarification_requested` or `escalation_offered`.

**Tests:** unknown source ID gives `fail/unknown_source`; stale version gives `fail/version_mismatch`; source removed after retrieval gives `fail/unresolvable_source`; access revoked gives `fail/access_denied`; answer with no citations gives `fail/no_citations`; all-valid citations give `pass`.

### C4. Human escalation

**Owner:** `EscalationService` (M6). **Authorization:** `customer` (own records).

**C4a. `POST /v1/escalations`**

| Field | Type | Req. | Nullable | Constraints |
|---|---|---|---|---|
| `submission_id` | Uuid | Yes | No | Generated once by the browser per intentional submission; reused on every retry |
| `reason` | EscalationReason | Yes | No | |
| `inquiry_id` | Uuid | No | Yes | Null when the customer requests a human directly; if present, must belong to caller |
| `content` | string | Yes | No | 1-1,000 chars; the customer-reviewed text (the prefilled question is only a suggestion) |
| `note` | string | No | Yes | 0-2,000 chars |
| `consent_to_share` | boolean | Yes | No | Must be `true` |

Unrelated conversation history is **not** attached automatically.

**Response 201 (new) / 200 (same `submission_id` and same content)**

| Field | Type | Notes |
|---|---|---|
| `request_id` | Uuid | The saved request |
| `submission_id` | Uuid | Echoed |
| `state` | RequestState | `queued` |
| `created_at` | Timestamp | |
| `acknowledgement` | string | Returned only after the durable commit. States that the request was saved, not that an agent has read it, and gives no response-time promise. |
| `correlation_id`, `contract_version` | | |

**Example request**
```json
{
  "submission_id": "5c4d3e2f-4444-4d55-8e66-2f77a88b99cc",
  "reason": "insufficient_evidence",
  "inquiry_id": "b1d2c3e4-1111-4a22-8b33-9c44d55e6f77",
  "content": "The 'Campus' VPN profile is missing after install.",
  "note": "Tried reinstalling twice.",
  "consent_to_share": true
}
```

**C4b. `GET /v1/escalations/{submission_id}`** (customer, own records). Returns `{ request_id|null, submission_id, state|null, saved: boolean, created_at|null }`. This lets the UI reconcile after a lost acknowledgment. If no record exists, returns 404 `NOT_FOUND`.

**C4c. `POST /v1/escalations/{request_id}/replies`** (customer, own record). Body `{ message: string (1-2,000 chars) }`. Allowed only in `waiting_for_customer`; moves the request back to `in_review`.

**Failure and duplicate behavior (Collins, Flow D)**

| Situation | Behavior |
|---|---|
| Validation fails | 400 `VALIDATION_FAILED` with field names; UI keeps the content; no receipt claimed |
| Save known to have failed | 503 `DEPENDENCY_UNAVAILABLE`; nothing stored; retry with the **same** `submission_id` |
| Save succeeded, acknowledgment lost | UI shows "confirmation pending" and calls C4b with the same `submission_id`, or retries C4a |
| Same ID, same content | 200 with the original `request_id`; no second record |
| Same ID, different content | 409 `CONFLICT`; the customer must submit deliberately as new (new `submission_id`) |
| Separate intentional request | New `submission_id` |
| Rate limit | 429 `RATE_LIMITED` |
| Escalation capacity bound | 503 `SERVICE_BUSY` (separate from generation capacity) |

**Idempotency and persistence.** Uniqueness of `(customer_scope [or tenant + customer], submission_id)` is enforced by an atomic constraint in shared durable storage. The idempotency record and the support request commit in one transaction. A disabled submit button is not the mechanism. If a queue broker is used, the stored request is the source of truth and a transactional outbox (or equivalent) prevents loss between commit and publish. Retention window: V11, open.
**Stored fields:** reviewed content, customer reference (from the trusted context), reason, originating inquiry reference, `submission_id`, timestamps, `state`, assigned agent.
**Privacy.** Content and note are not logged and are not sent to the AI provider.

**Tests:** first submit returns 201; same-ID retry returns 200 with one stored row; 20 concurrent same-ID submits create exactly one row; same ID with different content returns 409; save failure (mock) returns 503, no row, and the same-ID retry succeeds later; lost acknowledgment followed by C4b returns the saved request; `consent_to_share: false` returns 400; another customer's `inquiry_id` returns 403; administrator calling C4 returns 403.

### C5. Agent review and update

**Owner:** `AgentQueueService` (M6). **Authorization:** `agent` only. Customers and administrators get 403.

**C5a. `GET /v1/agent/escalations?state=queued&limit=25&cursor=...`**
`state` is optional. `limit` 1-100, default 25. Returns `{ items: [EscalationSummary], next_cursor|null }` with `EscalationSummary { request_id, state, content, reason, created_at, assigned_agent_id|null, customer_ref, version }`. Customer data is limited to the C7 allowlist.

**C5b. `POST /v1/agent/escalations/{request_id}/claim`**
No body. Atomic: succeeds only if `state = queued`; sets `assigned`, `assigned_agent_id = caller`, increments `version`. If another agent claimed first, 409 `CONFLICT`.

**C5c. `POST /v1/agent/escalations/{request_id}/transition`**

| Field | Type | Req. | Constraints |
|---|---|---|---|
| `to_state` | RequestState | Yes | Must be allowed below |
| `expected_version` | int | Yes | Optimistic check; mismatch returns 409 |
| `message_to_customer` | string | Cond. | Required for `waiting_for_customer`; 1-2,000 chars |
| `resolution_note` | string | Cond. | Required for `resolved`; 1-2,000 chars |

**Permitted transitions (proposed; Hanlin and David to review)**

| From | To | Who |
|---|---|---|
| `queued` | `assigned` | Any agent (via claim) |
| `assigned` | `queued` (release) | Assigned agent |
| `assigned` | `in_review` | Assigned agent |
| `in_review` | `waiting_for_customer` | Assigned agent |
| `waiting_for_customer` | `in_review` | System (customer reply, C4c) or assigned agent |
| `in_review` | `resolved` | Assigned agent |
| `resolved` | none | Terminal |

Any other transition, a non-owner update, or a stale version returns 409 `CONFLICT`. Conflicting updates never silently overwrite each other.

| Other conditions | Response |
|---|---|
| Not an agent | 403 `FORBIDDEN` |
| Unknown `request_id` | 404 `NOT_FOUND` |
| Missing conditional field | 400 `VALIDATION_FAILED` |
| Storage down | 503 `DEPENDENCY_UNAVAILABLE` |

**Audit.** Each transition records agent ID, old and new state, `correlation_id`, and timestamp, not content.

**Tests:** customer or administrator on any C5 endpoint returns 403; two concurrent claims give one 200 and one 409; non-owner transition returns 409; `resolved` then any transition returns 409; stale version returns 409; `waiting_for_customer` without a message returns 400; customer reply moves the request back to `in_review`; saved request visible in queue after a simulated broker failure.

### C6. Feedback and reviewed improvement

**Owner:** `FeedbackService` (M8). Learning is a **reviewed** loop. Feedback is evidence, not an instruction to the model and not an automatic training signal.

**C6a. `POST /v1/feedback`** (customer)

| Field | Type | Req. | Nullable | Constraints |
|---|---|---|---|---|
| `inquiry_id` | Uuid | Yes | No | Must belong to caller |
| `answer_id` | Uuid | Yes | No | Must belong to that inquiry |
| `rating` | enum `helpful`, `not_helpful` | Yes | No | |
| `category` | enum `incorrect`, `incomplete`, `wrong_source`, `unclear`, `too_much_escalation`, `other` | No | Yes | Only with `not_helpful` |
| `comment` | string | No | Yes | 0-500 chars |

Response 201: `{ feedback_id, state: "pending_review", correlation_id }`. The service stores the answer's `source refs` and `configuration_version` with the feedback.

**C6b. `GET /v1/agent/feedback?state=pending_review&limit=25`** (agent with reviewer permission) lists feedback with answer, source and configuration versions.

**C6c. Improvement proposals** (agent with reviewer permission)

| Endpoint | Purpose |
|---|---|
| `POST /v1/agent/improvements` | Propose a bounded change: `{ type: "knowledge_source"\|"retrieval"\|"prompt"\|"configuration", description (1-2,000), linked_feedback_ids (1-50) }` |
| `POST /v1/agent/improvements/{id}/review` | **Independent** reviewer approves or rejects, and records privacy-impact notes: `{ decision: "approve_for_evaluation"\|"reject", privacy_note (1-1,000) }`. Reviewer must differ from the proposer (else 409 `CONFLICT`). |
| `POST /v1/agent/improvements/{id}/evaluation` | Record the result against the fixed baseline: `{ baseline_id, report_ref, passed: boolean }` |
| `POST /v1/agent/improvements/{id}/release` | Allowed only if evaluation passed. Requires `rollback_ref`. Creates a new `configuration_version`. |
| `POST /v1/agent/improvements/{id}/rollback` | Restores the prior version; records reason |

**Proposal states:** `proposed`, `approved_for_evaluation`, `evaluated`, `released`, `rejected`, `rolled_back`. Skipping a state returns 409 `CONFLICT`.
A malicious or mistaken rating cannot change production behavior directly. It can only create review evidence.

| Condition | Response |
|---|---|
| Invalid enum, `category` with `helpful`, comment too long | 400 `VALIDATION_FAILED` |
| Inquiry or answer not the caller's | 403 `FORBIDDEN` |
| Duplicate feedback for the same answer | 409 `CONFLICT` |
| Customer or administrator on agent endpoints | 403 `FORBIDDEN` |
| Release without a passed evaluation or `rollback_ref` | 409 `CONFLICT` |

**Privacy.** Comments are visible only to authorized reviewers. Aggregates minimize identifiers. Raw feedback is not placed in the public repository. Retention: V21, open. Comments are not logged and not sent to the provider.
*Open (Vlad, Collins):* which role approves a release; this draft assumes agents with reviewer permission, and administrators do not see feedback content.

**Tests:** valid feedback returns 201 with versions stored; duplicate returns 409; the same person proposing and reviewing returns 409; release without evaluation returns 409; harmful proposal fails evaluation and cannot be released; rollback restores the prior `configuration_version`; administrator reading feedback returns 403.

### C7. Existing customer database

**Owner:** `CustomerDirectoryAdapter` (M7). Read-only in this draft. No real system is connected; the adapter is specified against a fictional "CustomerDB". The AI provider has no direct database connection.
**Method:** `get_customer_profile(ctx: AccessContext, customer_id: str, deadline_ms: int) -> CustomerProfile`
**Callers:** `InquiryService`, `EscalationService`. The `customer_id` must equal `ctx.customer_scope` for a customer; agents may look up the customer of a request they hold.

| Input | Constraints |
|---|---|
| `customer_id` | `^CUST-[0-9]{6}$`, e.g. `CUST-004821` |
| `deadline_ms` | 1-2000 |

**`CustomerProfile` (allowlist, V22):** `customer_id`, `display_name` (max 80), `tier` (`standard`, `priority`), `account_status` (`active`, `suspended`). Excluded: email, phone, address, payment and credential data. Adding a field requires a team decision.

| Condition | Behavior |
|---|---|
| Bad ID format | `InvalidCustomerId` (400) |
| ID outside caller's scope | `AccessDenied` (403) |
| Not found | `CustomerNotFound` (404) |
| Timeout or database down | `CustomerDirectoryUnavailable` |

**Failure handling**
- Inquiries that **require** customer context stop on failure and return a controlled escalation offer. The system does not guess customer facts. Which inquiries require context is open (V22).
- Inquiries that do not require context proceed without it.
- `EscalationService` always saves the request using the `customer_id` from trusted context, and enriches it later. A C7 outage never blocks escalation.
- Optional cache (proposed, open): keyed by customer and scope, short-lived, and invalidated on access change.
- *Open (Vlad):* whether any update operation is ever permitted. Draft assumes none.

**Tests:** valid ID returns only allowlisted fields; ID outside scope is denied; not found raises `CustomerNotFound`; timeout (mock) raises `CustomerDirectoryUnavailable` and escalation still saves; the AI request never contains non-allowlisted fields.

### C8. Document administration (new)

**Owner:** `DocumentService` (M3). **Authorization:** `administrator` only. Administrators cannot read customer conversations, escalations, or feedback content through any of these endpoints.

| Endpoint | Purpose |
|---|---|
| `POST /v1/admin/documents` | Create a document |
| `PUT /v1/admin/documents/{source_id}` | Replace a document. Creates a new `source_version`; prior versions retained so citations still resolve |
| `POST /v1/admin/documents/{source_id}/retire` | Retire a document; new retrievals exclude it, and C2b returns 404 for retired sections after the retention window (open) |
| `GET /v1/admin/documents` | List documents (`limit` 1-100) |

**Create/replace body**

| Field | Type | Req. | Constraints |
|---|---|---|---|
| `title` | string | Yes | 1-120 chars |
| `visibility` | enum `customer`, `agent` | Yes | Controls retrieval scope |
| `sections` | array of `{ section_id, title, text }` | Yes | 1-30 sections; `section_id` matches `^s[0-9]{1,2}$` and is unique; `text` 1-5,000 chars |

Response: `{ source_id, source_version, index_status: "rebuilding"|"ready", correlation_id }`. Source IDs stay stable across versions. Invalid input is rejected.

| Condition | Response |
|---|---|
| Invalid body, duplicate `section_id` | 400 `VALIDATION_FAILED` |
| Not an administrator | 403 `FORBIDDEN` |
| Unknown `source_id` | 404 `NOT_FOUND` |
| Index rebuild fails | 503 `DEPENDENCY_UNAVAILABLE`; previous version stays active |

**Tests:** replace creates version 4 while `DOC-003` v3 still resolves; invalid section ID returns 400; customer or agent calling C8 returns 403; failed rebuild leaves the prior version active; retired document no longer retrieved.
